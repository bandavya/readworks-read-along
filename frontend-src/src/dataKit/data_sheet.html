The path, from a student's device to the teacher's

Student's deviceThe teacher sends one link to the class. The student picks their name and reads.
  • The screen says what the teacher will see
  • Picking "I'm not on this list" sends nothing
  • Only the assigned passage reports
→
ServerKeeps one small record per student per assignment.
  • Refuses any field not on its list, so a word can't be stored
  • Set to expire after 14 days
  • Tested on a local copy so far, not yet on AWS; on ReadWorks' systems in real use
→
Teacher's computerA private class link opens the dashboard, whenever the teacher chooses.
  • No alerts, no live feed: it loads when opened
  • Alphabetical, never ranked
  • Reads the class only with that link's secret key
Stays on the student's device: running counts, speed, voice, saved words.

The biggest limit today: nothing checks who a student is. Without real sign-in, anyone with the class link can see every name on the list and report as any of them, so a dashboard row could be wrong or falsified. Your policy also says a student's name is visible only to their own teacher, and this list isn't. It's for demos with made-up students. Real use needs ReadWorks' sign-in.

What it can help a teacher do

  • See who hasn't opened it, and check in kindly
  • Spot audio that won't play, and fix it rather than blame a child
  • Notice who's using the tools

What it can't tell a teacher

  • Whether a student read or understood
  • Why a student used a tool: curiosity and difficulty look the same
  • Reading on paper, or with sound off
  • A reading level

Left out on purpose

  • Which word was tapped
  • How many times
  • Minutes, or time of day
  • Any score, flag or ranking

Research on a children's reading tutor found raw help counts mislead, which is why we send a yes rather than a count.

File counts come from a development server, which sends many small files. Of the 6, one read the name list and 5 sent progress. Google Fonts was 4 in an earlier run, before the browser saved them. Cookies set: none.

  • Automated checks: on the kit, including that its data files hold no network calls and that a normal report holds only the three fields shown; and on the server, including refused fields and the teacher's key. All pass. They don't cover the falsified-row limit above, which an outside review reproduced.
  • End to end, on this computer: a teacher made a class, a student in another browser tab picked a name and read, and the teacher's dashboard showed that student's row and the others as not opened. This used a local copy of the server code, not AWS, and a real class on real devices hasn't been tried.
  • A search of the reader's code: found no microphone, camera, location, cookies or analytics tools. That's a search, not a guarantee about every future build.
  • Outside AI reviews: another company's model audited this page against the code twice, and each time we fixed or disclosed what it found. It also plugged the kit into a clean copy of the app. No person has done any of this.

Before any real student uses this

This hasn't been cleared for real students, and it shouldn't run with them on our test account. A class dashboard holds records about named children, which is a bigger step than counts on a device.

For ReadWorks to decide

  • Your policy says you don't collect "behavioral data", and store use activity "anonymously". A named dashboard doesn't fit that wording as it stands
  • Who operates it, under which school agreements
  • How long records stay
  • Whether teachers should see library reading (we've kept it out)

Questions for counsel

  • Whether these records count as education records under FERPA, in a school's hands
  • How your position on COPPA and FERPA applies to a teacher dashboard
  • Which state student-privacy laws and contracts apply. We found no nonprofit exclusion in the New York, California or Illinois text we read, but that's not a legal opinion
  • How parents can see or delete a child's record

What we'd need to build

  • Your real student sign-in, in place of picking a name
  • Your server, in place of ours
  • Feedback form off for students, and Google Fonts out
  • A view for each student of their own row
  • A security review by a person
  • Testing with real teachers on how they read "partway"
