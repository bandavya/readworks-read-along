# Data flow

*Where does one passage and its audio go before a student taps a word?*

The data · Status: built and tested locally

A content teammate starts with a passage: its words, title, ID, and any reading help. Sound Along makes a recording from those words, checks the sound and word starts, then prepares a separate copy for the reader. The source and working recording stay in private storage. The website gets its own copy of the recording, a full story record, a short library entry, and, on the Ruth setup, pronunciation-guide clips in the passage voice.

The job row follows the work. It lets the workflow reuse a matching completed recording and shows whether generation or reader publication failed. The library entry is written after the copied sound and story record. When a student opens that story, the website loads the record. Tapping a numbered word seeks the copied sound to that word's time. The live Ruth setup has the voice check on; the default Joanna setup has it off. Signed submission is off in both unless enabled.

**The browser uses website copies; the source, working audio, and job state stay in separate places.**

## Technical details

`lib/sound-along-stack.ts` creates three private S3 buckets (`ContentBucket`, `AudioBucket`, `FrontendBucket`) and the DynamoDB `JobTable`, keyed by `passageId` and `textHash`. An object-created notice for `passages/*.json` calls `lambdas/trigger/handler.py`, which starts the workflow with the ID and source key. `lambdas/worker/handler.py` reads `text`, collapses whitespace, and hashes the result with voice, engine, and language. A matching finished job can skip synthesis; a job with media but no reader publication can retry the bridge.

| Thing | Where it lives | Who writes it | Who reads it |
|---|---|---|---|
| Source `passages/<id>.json` | Content bucket | Direct uploader, `scripts/seed.js`, or optional `lambdas/passage_service/handler.py` | Trigger gets its key; worker and reader bridge read the source. |
| Optional `api-jobs/<id>.json` | Content bucket | Signed passage service, when `passageApi=true` | Same service reads the submission marker for idempotency and status. |
| Running and finished job row | `JobTable` | Worker; optional quality gate; reader bridge | Worker checks the exact ID and hash for reuse; passage service and browser API read status. |
| Polly task MP3 and raw marks under `polly/<audioId>/audio/` and `polly/<audioId>/marks/` | Audio bucket | Polly synthesis tasks | Worker validates both outputs; optional recognition reads the MP3. Exact leaf keys come from Polly's returned output URI. |
| Optional `transcribe/<job>.json` | Audio bucket | Speech recognition, when `qualityGate=true` or `generativeVoice=true` | Quality gate compares heard words; generative voice code makes timing marks. |
| Canonical `audio/<audioId>.mp3` and `audio/<audioId>.speechmarks.json` | Audio bucket | Worker copies MP3 and writes normalized JSON marks after checks | Reader bridge copies sound and reads marks; passage service checks both for status. |
| Optional `review/<id>.json` | Content bucket | Quality gate on a held result | Passage service reads the hold reasons. |
| `manifests/<id>.json` | Content bucket | Worker, after checks | Passage service reads media keys and generation status. |
| `content/<id>.json` | Content bucket | Worker copies the source and adds `au` and `audioManifest` | Browser API and passage service read the published derivative. |
| `audio/<id>/<digest>.mp3` | Frontend bucket | Reader bridge copies canonical MP3 | Browser loads the voice's relative audio path through the site delivery network. |
| `data/<id>.json` | Frontend bucket | Reader bridge numbers displayed words and builds `voices[].t` | `frontend-src/src/api.js` loads it; `soundAlong.js` and `engine/input.js` use the timing on a tap. |
| `audio/syl/*.mp3`, `data/syllables/<id>.json` | Frontend bucket | Reader bridge calls `lambdas/syllable_audio/` when `SYLLABLE_AUDIO=true` and vocabulary exists | The reader's Words to know guide loads whole-word, syllable, and slow clips. |
| `data/index.json` | Frontend bucket | Reader bridge writes it last; `scripts/publish-frontend.js` can merge a local list with live rows | `frontend-src/src/api.js` loads the library list. |
| `index.html`, `assets/*`, `experiments.json` | Local `frontend/`, then Frontend bucket when published | Local `scripts/build-frontend.js`; `scripts/publish-frontend.js` uploads them | Browser loads the website shell; the build does not create passage media. |

The default voice is Joanna with Polly neural speech marks and the voice check off. The team reports that the deployed setup uses `generativeVoice=true` for Ruth and speech recognition for word starts. Its build doc also lists `qualityGate=true`, a heard-word check that can hold a take, but its deploy command doesn't turn that on. `SYLLABLE_AUDIO` is on with `generativeVoice` unless `-c syllableAudio=false`; Joanna uses the older guide clips. The stack grants the bridge Polly permission whenever `generativeVoice=true`, including when guide audio is switched off; this is broader than the build doc's switch description. `passageApi=true` adds signed intake and writes both `api-jobs/<id>.json` and `passages/<id>.json`; the team reports it is off on the live setup. `readerBridge=false` removes website publication. These are stack settings, not student controls. The reader's default static route in `frontend-src/src/api.js` fetches `data/index.json` and `data/<id>.json`; its separately configured managed-data route uses a different document contract.

The reader bridge validates marks against source words and formatted content before writing the website copy. It writes the MP3, then `data/<id>.json`, then `data/index.json`, then optional guide files, and finally records `readerPublishedAt` on the job row. A guide-level failure records `syllableAudioError` without failing publication; a failed word can leave an empty guide entry. A timeout before the final job update could mark a live passage failed. Guide clip paths omit the voice and are cached for a year, so a different voice can keep serving old clips. On publication mismatch the bridge records `reader_publish_failed`; a retry can reuse the media. Reuse requires `approved` for Joanna's default path or `generated` for the checked path, with the same ID and text hash. The index update retries a read/write confirmation, but has no transactional lock. The public site has no sign-in, and the legacy `/generate` route can start paid runs without a credential; there is no human approval before generated sound reaches students. To check locally from `base/`, run `npm run build`, `npm run synth`, `python tests/test_reader_bridge.py`, and `node tests/test_publish_frontend.cjs`.
